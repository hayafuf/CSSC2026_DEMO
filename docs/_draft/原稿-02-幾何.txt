## 3-1 このファイルの役割

config.js は **ロジックを1行も持ちません**。やることは2つだけです。

  1. window.PP という名前空間を作る
  2. ゲーム中で使う定数と、みんなで共有する状態を PP にぶら下げる

  js/config.js:8
    var PP = window.PP = {};

この1行が、他の15ファイルすべての前提になります。だから index.html で
config.js を一番最初に読んでいます。

「マジックナンバーを1か所に集める」というのは地味ですが強力な設計です。
たとえば玉の半径を変えたくなったとき、PP.R を書き換えるだけで、
玉の絵・当たり判定・玉の間隔・トンネルの太さが全部ついてきます。


## 3-2 いちばん大事な2つの定数

  js/config.js:13-14
    PP.R = 24;              // 玉の半径
    PP.D = PP.R * 2;        // 玉の間隔(直径)

D = 48 は、このゲームで最も頻繁に出てくる数です。理由は簡単で、
**玉がぴったり接触しているとき、2つの玉の d の差はちょうど D** だからです。

  玉A の d = 1000
  玉B の d = 1048    → 接触している

これがあるので、コード中に何度もこういう比較が出てきます。

  balls[i-1].d - balls[i].d > D + 0.5      → 隙間が空いている(別グループ)
  balls[i].d < balls[i+1].d + D            → めり込んでいる(押し出しが要る)
  t.d - balls[i+1].d <= D + 0.5            → 接触している

+0.5 や +1 は「浮動小数点の誤差で 48.0000001 になっても接触扱いにする」ための
遊びです。コンピュータの小数計算はぴったり 48 にならないことがあるので、
こういう「イプシロン」を足すのは定石です。

画面サイズも定数です。

  js/config.js:11-12
    PP.W = 1300;
    PP.H = 700;

canvas の実サイズと一致しています(index.html:165)。
CSS で拡大縮小しても、コードの中では常にこの 1300×700 で考えます。


## 3-3 速度のプロファイル

  js/config.js:35-39
    PP.SPEED_ENTRY = 600;   // 洞窟付近の速度 px/s
    PP.SPEED_HOLE = 18;     // 樽の直前の速度 px/s
    PP.SPEED_CURVE = 1.8;   // 減速カーブの指数
    PP.LEVEL_SPEED = 0.06;  // レベルごとの速度倍率の加算
    PP.ROLLOUT_BOOST = 2.2; // レベル開始時のなだれ込み加算倍率

チェーンの速度は「一定」ではありません。洞窟を出た直後は 600 px/s と速く、
樽に近づくと 18 px/s までゆっくりになります。

これはゲームデザイン上の判断です。速度が一定だと、
・序盤: 遠いのでヒマ
・終盤: 速いままなので何もできずに死ぬ
となります。「遠いうちは速く流れて、危なくなるほどゆっくり」だと、
プレイヤーは終盤に考える時間を持てます。

実際の計算式は chain.js にあります(章06 で詳しく)。

  js/chain.js:150-151
    var v = PP.SPEED_HOLE +
            (PP.SPEED_ENTRY - PP.SPEED_HOLE) * Math.pow(1 - t, PP.SPEED_CURVE);

t は 0(洞窟)〜1(樽)の進み具合。t=0 なら (1-0)^1.8 = 1 なので v = 600。
t=1 なら 0^1.8 = 0 なので v = 18。指数 1.8 は「後半でぐっと落ちる」形にします。


## 3-4 磁力と反動の定数

チェーンの一番おもしろい挙動が、この2つです。

  js/config.js:52-54
    PP.ATTRACT_SPEED = 250;        // 磁力の初速 px/s
    PP.ATTRACT_ACCEL = 1300;       // 磁力の加速度 px/s^2
    PP.ATTRACT_MAX = 640;          // 磁力の最高速 px/s

  js/config.js:64-66
    PP.RECOIL_RATIO = 0.5;         // 衝突速度のうち後方列に伝わる割合
    PP.RECOIL_DAMP = 2.4;          // 反動の減衰係数 (1/s)
    PP.RECOIL_MAX = PP.D * 2;      // 1回の反動で下がる最大距離(= 96px)

  js/config.js:80
    PP.BOUNCE_COOLDOWN = 1.0;

BOUNCE_COOLDOWN のコメントには、これが無いと何が起きるかが書かれています。

  「入れないと『衝突 → 反動で隙間が開く → 反動が終わる → 同じ色なので磁力が
    また閉じる → 二度目の衝突』となり、同じ場所でトン、トンと二度跳ねる。」

これは実装してみないと気づかない類のバグです。ぶつかった2玉を1秒間だけ
「磁力の対象外」にすることで、この振動を止めています。

「時定数」という言葉が何度か出てきます。

  js/config.js:60
    PP.COAST_DECAY = 0.5;   // 巻き戻りの慣性の減衰時定数(秒)

これは指数関数的な減衰の速さを表す数です。

  速度 = 初速 × exp(-経過時間 / 時定数)

時定数が 0.5 秒なら、0.5 秒後に速度は約 37%(1/e)、1 秒後に約 14% になります。
コードでは Math.exp(-dt / PP.COAST_DECAY) を毎フレーム掛ける形で書かれます。
これなら dt がばらついても、結果が同じになります(フレームレート非依存)。


## 3-5 色のパレット

  js/config.js:205-212
    PP.PALETTE = [
      { light: "#ff6a4a", main: "#e01810", dark: "#4d0708", edge: "#1c0202" }, // 赤
      { light: "#5aa8ff", main: "#0d5ce0", dark: "#05204d", edge: "#020c1e" }, // 青
      { light: "#5cf065", main: "#12a828", dark: "#043a10", edge: "#011505" }, // 緑
      { light: "#ffd24a", main: "#ef9405", dark: "#5f3301", edge: "#241300" }, // 黄
      { light: "#c46ffb", main: "#8a20d8", dark: "#33075c", edge: "#130121" }, // 紫
      { light: "#ffffff", main: "#d6cdb4", dark: "#6a6252", edge: "#26221a" }  // 骨白
    ];

玉の color プロパティは、この配列の添字(0〜5)です。
色そのもの("#e01810")ではなく番号で持つ理由は、比較が速くて確実だからです。

  if (balls[i].color === balls[j].color)   ← 数値の比較。1命令

1色あたり4つの色を持っているのは、球体のシェーディングのためです。

  light  左上のハイライト/リムライト
  main   胴の色(その玉の「色」として認識される部分)
  dark   下側の陰
  edge   輪郭に近い最暗部

  js/config.js:217
    PP.COLORS = { base: 4, perLevel: 1, max: 6, levelStep: 3 };

色数はレベルで増えます。計算は main.js にあります。

  js/main.js:120-121
    g.nColors = Math.min(c.max,
      c.base + Math.floor((g.level - 1) / c.levelStep) * c.perLevel);

  レベル1〜3 → 4 + floor(0/3 or 1/3 or 2/3)*1 = 4色
  レベル4〜6 → 4 + 1 = 5色
  レベル7〜  → 4 + 2 = 6色(max で頭打ち)

色が増えると難しくなる理由は、config.js:215 に実測値があります。

  「実測(塊率0.26): 4色→先頭に効く弾 96%/列5個、5色→89%/11個、6色→81%/19個」

つまり「撃つ玉の色が、いま一番危ない先頭の玉に噛み合う確率」が下がり、
その結果として盤面に残る列がどんどん長くなります。


## 3-6 レールの制御点 PP.CTRL

  js/config.js:230-248
    PP.CTRL = [
      // 1段目(洞窟から左へ)y=104
      [1450, 104], [1244, 104], [1050, 104], ... [96, 104],
      [68, 118], [56, 146], [68, 174],       ← 左端で U ターン
      // 2段目(右へ)y=188
      [96, 188], [318, 188], ... [1204, 188],
      [1232, 202], [1244, 230], [1232, 258], ← 右端で U ターン
      ...
    ];

これは「道が通る目印の点」の並びです。[x, y] のペアが 57 個。
これをそのまま線で結ぶとカクカクしますが、rail.js が滑らかな曲線に変換します。

コメント(js/config.js:225-229)に設計の制約が書かれています。

  ・縦に使えるのは HUD の下端(62)〜砲口の先(約620)しかない
  ・1段目 y=104、段間 84px で6段 = y=104〜524
  ・全長は横幅で稼ぐ。各段を x=96 〜 x=1204 まで伸ばす
  ・洞窟(d=0)は画面右外の x=1450。玉は画面の外から流れ込んでくる

「大砲は真上撃ちなので、どの段も水平に保って狙えるようにしてある」というのが
一番効いている判断です。段が斜めだと、真上に撃つゲームとして狙いにくくなります。

3つ目の要素を持つ点もあります。

  js/config.js:313
    { ctrl: [ [-120, 450], [350, 450, 0], [350, 100, 0], ... ] }

3つ目の 0 は「この点は角にする(滑らかに丸めない)」という指定です。
rail.js の sharp() 関数がこれを見ます(4-6 節で説明)。


## 3-7 コース定義 PP.COURSES

  js/config.js:276-356

6つのコースが定義されています。

  0 航路           1レーンの6段蛇行(PP.CTRL)
  1 橋を渡る道      1レーンだが自己交差する。sharp:true の直角の道
  2 エディタのコース  2レーン。左右対称のループと中央の交差
  3 四叉の激流      4レーン。serpLane() で作った短い蛇行が4本
  4 洞窟航路        コース0にトンネルを2つ掘ったもの
  5 交わる航路      2レーンが画面中央で X 字に交差

コースの中身は「レーンの配列」だけです。

  { name: "航路", overpass: false, lanes: [ { ctrl: PP.CTRL } ] }

  name      表示名
  overpass  true にすると、自己交差を自動検出して立体交差(橋)にする
  sharp     true にすると直角の街路になる(角丸あり)
  corner    sharp のときの角丸半径
  lanes     レーンの配列。各レーンは { ctrl, tunnels?, raised? }

lane の tunnels と raised は、どちらも「レール全長に対する割合」で区間を指定します。

  js/config.js:340
    tunnels: [ { from: 0.30, to: 0.42 }, { from: 0.62, to: 0.72 } ]

  → 全長の 30%〜42% と 62%〜72% がトンネル(玉が隠れて撃てない)

  js/config.js:315
    raised: [ { from: 0.79, to: 0.86 } ]

  → 全長の 79%〜86% でこのレーンが「橋(上)」になる

割合で指定するのは、コースの長さが変わっても壊れないようにするためです。

serpLane() は、同じ形のレーンを座標だけ変えて量産するヘルパです。

  js/config.js:254-265
    function serpLane(cx, halfW) {
      var Lx = cx - halfW, Rx = cx + halfW;
      var ys = [110, 190, 270, 350, 430, 510];
      var pts = [[cx, -140]];         // 洞窟(画面上外)
      var atLeft = true;
      for (var r = 0; r < ys.length; r++) {
        pts.push([atLeft ? Lx : Rx, ys[r]]);   // 段の入口
        pts.push([atLeft ? Rx : Lx, ys[r]]);   // 段の出口
        atLeft = !atLeft;
      }
      return pts;
    }

atLeft を毎段反転させることで、左→右→左→右…と往復する蛇行になります。
牛が畑を耕すときの往復に似ているので「ボストロフェドン」と呼ばれる形です。

effects は「残り秒数」です。0 なら効果なし。powerups.js が毎フレーム減らし、

最後の2つはヘルパ関数です。

  js/config.js:420-432
    eachLane: function (cb) {
      for (var i = 0; i < this.lanes.length; i++) {
        if (cb(this.lanes[i], i) === false) return;
      }
    },
    eachLaneBall: function (cb) {
      for (var i = 0; i < this.lanes.length; i++) {
        var lane = this.lanes[i], balls = lane.balls;
        for (var j = 0; j < balls.length; j++) {
          if (cb(balls[j], lane, j, i) === false) return;

「全レーンを回る」「全レーンの全玉を回る」という二重ループが
あちこちで必要になるので、1か所にまとめたものです。

コールバックが false を返したら打ち切る、という約束になっています。
これは「見つかったらすぐ抜けたい」場面のためです。

  js/main.js:199-204
    g.eachLane(function (lane) {
      if (lane.balls.length > 0 &&
          lane.balls[0].d >= lane.rail.holeD + PP.D * PP.BARREL_CAPACITY) {
        dead = true; return false;    ← ここで打ち切り
      }

普通の for ループなら break が使えますが、コールバック方式では break が
使えません。だから「false を返したら return する」という取り決めを作っています。

## 4-1 このファイルが解く問題

  「[x, y] の点が 57 個ある。これを滑らかな道にして、
   『洞窟から 1200px 進んだ地点の座標』を高速に答えられるようにせよ。」

これだけです。解き方は2段階。

  ステップA: 制御点 → 滑らかな曲線 → 細かい折れ線(xs[], ys[])
  ステップB: 折れ線 → 弧長テーブル(cum[])→ 二分探索で posAt(d)

順に見ていきます。


## 4-2 「工場」としての rail

  js/rail.js:312-316
    PP.rail = {
      create: create,
      measure: measure,
      courseCrossings: courseCrossings
    };

PP.rail は「レールそのもの」ではなく「レールを作る工場」です。
PP.rail.create(course, laneIndex) を呼ぶと、そのレーン専用のレールが返ってきます。

  js/main.js:39
    rail: PP.rail.create(course, i),

なぜ工場にしたのか。コース3(四叉の激流)のように **4本のレールが同時に走る**
からです。もし PP.rail が1本ぶんのデータを直接持っていたら、4本を同時に
扱えません。

これは JavaScript の「クロージャ」という仕組みを使っています。

  js/rail.js:236-309
    function create(course, laneIndex) {
      var pl = measure(course, laneIndex);
      var xs = pl.xs, ys = pl.ys, cum = pl.cum;    ← この関数のローカル変数
      var length = pl.length;
      var holeD = length - 6;
      ...
      function posAtInto(d, out) {
        ... xs, ys, cum を使う ...       ← 外側の変数を覚えている
      }
      return { posAt: posAt, posAtInto: posAtInto, ... };
    }

create の中で作った xs/ys/cum は create が終わっても消えません。
返された posAtInto がそれを参照しているからです。
create を2回呼べば、それぞれ別の xs/ys/cum を持つ2組が手に入ります。

これが「クロージャによるインスタンス生成」です。class を使わずに
同じことができます。


## 4-3 Catmull-Rom スプライン

制御点を滑らかにつなぐ方法はいくつもありますが、このゲームは
**Catmull-Rom(キャットマル・ロム)スプライン** を使っています。

一番の特徴は **すべての制御点を必ず通る** ことです。
(ベジェ曲線は制御点を通らないので、道の設計には向きません)

  js/rail.js:114-119
    function catmull(p0, p1, p2, p3, t) {
      var t2 = t * t, t3 = t2 * t;
      return 0.5 * ((2 * p1) + (-p0 + p2) * t +
        (2 * p0 - 5 * p1 + 4 * p2 - p3) * t2 +
        (-p0 + 3 * p1 - 3 * p2 + p3) * t3);
    }

引数の意味:

  p1, p2   いま結びたい2点(この区間を描く)
  p0, p3   その前後の点(曲がり具合を決めるのに使う)
  t        0 なら p1、1 なら p2。その間を補間する

式の読み方を、t を代入して確かめてみます。

  t = 0 のとき:
    0.5 * (2*p1 + 0 + 0 + 0) = p1      ← ちゃんと p1 を通る

  t = 1 のとき:
    0.5 * (2*p1 + (-p0+p2) + (2*p0-5*p1+4*p2-p3) + (-p0+3*p1-3*p2+p3))
    = 0.5 * (2*p1 - p0 + p2 + 2*p0 - 5*p1 + 4*p2 - p3 - p0 + 3*p1 - 3*p2 + p3)
    = 0.5 * (0*p0 + 0*p1 + 2*p2 + 0*p3)
    = p2                               ← ちゃんと p2 を通る

p0 と p3 は「前後の点がどこにあるか」で曲がり方を変えるために使われます。
直感的には「p1 での接線の向きを p0→p2 の方向にする」「p2 での接線の向きを
p1→p3 の方向にする」という決め方です。

なお、この関数は x と y を別々に計算します(1次元の補間を2回)。

  js/rail.js:128-129
    ox.push(catmull(p0[0], p1[0], p2[0], p3[0], t));
    oy.push(catmull(p0[1], p1[1], p2[1], p3[1], t));

【GIF: rail/catmull-rom.gif】
  4つの制御点を置き、t を 0→1 と動かすと点が p1 から p2 へ動く。
  p0 と p3 をドラッグすると曲線の膨らみが変わることを見せる。


## 4-4 曲線を折れ線にする

コンピュータは曲線をそのままでは扱えません。細かい直線の集まりに変換します。

  js/rail.js:120-134
    for (var i = 0; i < CTRL.length - 1; i++) {
      var p0 = pt(sharp(i) ? i : i - 1);
      var p1 = pt(i), p2 = pt(i + 1);
      var p3 = pt(sharp(i + 1) ? i + 1 : i + 2);
      var steps = 24;
      for (var s = 0; s < steps; s++) {
        var t = s / steps;
        ox.push(catmull(p0[0], p1[0], p2[0], p3[0], t));
        oy.push(catmull(p0[1], p1[1], p2[1], p3[1], t));
      }
    }
    ox.push(CTRL[CTRL.length - 1][0]);
    oy.push(CTRL[CTRL.length - 1][1]);

各区間を 24 分割しています。制御点が 57 個なので区間は 56 個、
折れ線の点は 56 × 24 + 1 = 1345 個になります。

最後の1点を別に push しているのは、内側のループが s < 24 で
t = 24/24 = 1 を含まないからです(含めると次の区間の t=0 と重複します)。

pt() 関数は配列の範囲外アクセスを防ぐヘルパです。

  js/rail.js:110
    function pt(i) { return CTRL[Math.max(0, Math.min(CTRL.length - 1, i))]; }

i が -1 なら 0 番、i が length なら最後の点を返します。
これで端の区間でも p0/p3 が undefined にならずに済みます。

sharp() は「この点は角にする」フラグの判定です。

  js/rail.js:113
    function sharp(i) { var p = CTRL[i]; return !!p && p.length > 2 && p[2] <= 0.5; }

制御点が [x, y, 0] のように3つ目を持ち、その値が 0.5 以下なら角。
角のときは p0 を i-1 ではなく i 自身にすることで、
「その点で接線を切る」= 滑らかにつながずカクッと折れる、という効果を出します。

【GIF: rail/spline-to-polyline.gif】
  制御点列 → 各区間を 24 分割してサンプル → 折れ線が出来上がる。
  分割数を 4 / 8 / 24 と変えたときのガタつきの違いも並べる。


## 4-5 弧長テーブル

ここが rail.js の核心です。

折れ線ができても、「洞窟から 1200px 進んだ地点」はまだ分かりません。
折れ線の点は等間隔ではないからです(カーブの内側では密、直線では疎)。

そこで **「先頭からその点までの累積距離」を配列に持ちます**。これが弧長テーブル。

  js/rail.js:189-192
    for (var i = 1; i < ox.length; i++) {
      var dx = ox[i] - ox[i - 1], dy = oy[i] - oy[i - 1];
      oc.push(oc[i - 1] + Math.sqrt(dx * dx + dy * dy));
    }

やっていることは単純です。

  cum[0] = 0
  cum[1] = cum[0] + (点0 と 点1 の直線距離)
  cum[2] = cum[1] + (点1 と 点2 の直線距離)
  ...

Math.sqrt(dx*dx + dy*dy) は三平方の定理。2点間の距離です。

こうしておくと、

  cum[500] = 3210.5

なら「500 番目の点は、洞窟から 3210.5px の地点にある」と分かります。

  js/rail.js:193
    return { xs: ox, ys: oy, cum: oc, length: oc[oc.length - 1] || 0, ctrl: CTRL };

length は最後の cum、つまりレール全長です。コース0 だとおよそ 8700px。
玉の直径が 48px なので、およそ 181 個の玉が並ぶ長さです。

【GIF: rail/arc-length-table.gif】
  折れ線の点を1つずつたどりながら cum[] の棒グラフが伸びていく。
  カーブでは点が密なので cum の増え方が小さく、直線では大きいことが見える。


## 4-6 直角の道 buildSharp

コース1(橋を渡る道)は sharp: true です。こちらは Catmull-Rom を使わず、
直線でつないで角だけ丸めます。

  js/rail.js:161-178
    push(CTRL[0][0], CTRL[0][1]);
    for (var i = 1; i < CTRL.length - 1; i++) {
      var A = CTRL[i - 1], B = CTRL[i], C = CTRL[i + 1];
      var d1 = norm(B[0] - A[0], B[1] - A[1]);   // A→B の単位ベクトル
      var d2 = norm(C[0] - B[0], C[1] - B[1]);   // B→C の単位ベクトル
      var lenIn = Math.hypot(B[0] - A[0], B[1] - A[1]);
      var lenOut = Math.hypot(C[0] - B[0], C[1] - B[1]);
      var pr = (B.length > 2 && isFinite(B[2])) ? B[2] : rc;
      var r = Math.min(pr, lenIn / 2, lenOut / 2);
      var t1x = B[0] - d1[0] * r, t1y = B[1] - d1[1] * r;   // 角の手前
      var t2x = B[0] + d2[0] * r, t2y = B[1] + d2[1] * r;   // 角の先
      line(前の点, t1x, t1y);
      quad(t1x, t1y, B[0], B[1], t2x, t2y);                 // 角丸
    }

  「単位ベクトル」とは、向きだけを表す長さ1の矢印のことです。
  norm() は与えられたベクトルを長さ1に直します。

  js/rail.js:159
    function norm(dx, dy) { var l = Math.sqrt(dx * dx + dy * dy) || 1; return [dx / l, dy / l]; }

角 B の手前 r px の点 t1 まで直線を引き、そこから角 B を制御点にした
二次ベジェで t2 まで曲げ、その先はまた直線。これで角が丸くなります。

  js/rail.js:151-158
    function quad(ax, ay, cxp, cyp, bx, by) {
      var n = 8;
      for (var k = 1; k <= n; k++) {
        var t = k / n, u = 1 - t;
        push(u * u * ax + 2 * u * t * cxp + t * t * bx,
             u * u * ay + 2 * u * t * cyp + t * t * by);
      }
    }

これは二次ベジェの式そのものです。

  B(t) = (1-t)² × 始点 + 2(1-t)t × 制御点 + t² × 終点

角丸半径のクランプが重要です。

  var r = Math.min(pr, lenIn / 2, lenOut / 2);

もし r が辺の長さの半分より大きいと、丸めた部分が前後の角と食い合って
道がねじれます。「辺の半分まで」で止めることで、どんな形の角でも破綻しません。

【GIF: rail/sharp-corner.gif】
  直線 → 角の手前 t1 → 二次ベジェで丸め → 角の先 t2 → 直線。
  角丸半径を大きくしていくと min() でクランプされて止まる様子も見せる。

push() には間引きも入っています。

  js/rail.js:140-144
    function push(x, y) {
      var n = xs.length;
      if (n > 0) { var dx = x - xs[n - 1], dy = y - ys[n - 1]; if (dx * dx + dy * dy < 0.25) return; }
      xs.push(x); ys.push(y);
    }

前の点と 0.5px 未満しか離れていなければ捨てます。
同じ位置の点が並ぶと弧長テーブルに 0 が並び、後の二分探索で
0 除算やゼロ長セグメントの原因になるためです。

(0.25 は 0.5 の2乗。sqrt を避けるために2乗のまま比較しています。
 これは距離比較の常套手段で、コード中で何度も出てきます)


## 4-7 posAtInto — 距離から座標へ

いよいよ本命です。

  js/rail.js:253-268
    function posAtInto(d, out) {
      if (d <= 0) d = 0;
      if (d >= length) d = length - 0.001;
      var lo = 0, hi = cum.length - 1;
      while (lo + 1 < hi) {
        var mid = (lo + hi) >> 1;
        if (cum[mid] <= d) lo = mid; else hi = mid;
      }
      var seg = cum[hi] - cum[lo] || 1;
      var t = (d - cum[lo]) / seg;
      out.x = xs[lo] + (xs[hi] - xs[lo]) * t;
      out.y = ys[lo] + (ys[hi] - ys[lo]) * t;
      out.tx = (xs[hi] - xs[lo]) / seg;
      out.ty = (ys[hi] - ys[lo]) / seg;
      return out;
    }

3段階です。

【① 二分探索で、d を挟む2点を見つける】

  var lo = 0, hi = cum.length - 1;
  while (lo + 1 < hi) {
    var mid = (lo + hi) >> 1;
    if (cum[mid] <= d) lo = mid; else hi = mid;
  }

cum は必ず増加していく配列(単調増加)なので、二分探索が使えます。

真ん中を見て、d より小さければ「答えは右半分」、大きければ「左半分」。
毎回範囲が半分になるので、点が 1345 個あっても 11 回で見つかります。
(2^11 = 2048 > 1345)

もし前から順に探したら、平均 672 回。玉が 100 個あれば毎フレーム 67200 回。
二分探索なら 1100 回。60 倍の差です。

  (lo + hi) >> 1

は「2で割って小数を切り捨てる」ビット演算です。
Math.floor((lo+hi)/2) と同じですが、こちらのほうが速く書けます。

ループの終了条件が `lo + 1 < hi` なのがポイントで、
終わったとき **hi は必ず lo + 1** になっています。つまり隣り合う2点です。

【② 線形補間で座標を出す】

  var seg = cum[hi] - cum[lo] || 1;
  var t = (d - cum[lo]) / seg;
  out.x = xs[lo] + (xs[hi] - xs[lo]) * t;
  out.y = ys[lo] + (ys[hi] - ys[lo]) * t;

seg はこのセグメントの長さ。t は「このセグメントの何割の位置か」。
あとは lo の座標から hi の座標へ、t の割合だけ進めばいい。

`|| 1` は seg が 0 のときに 0 除算を避ける保険です。

【③ 接線ベクトルも返す】

  out.tx = (xs[hi] - xs[lo]) / seg;
  out.ty = (ys[hi] - ys[lo]) / seg;

「接線」とは、その地点で道が向いている方向のことです。
セグメントの向きベクトルを長さで割って、長さ1に正規化しています。

この接線が何に使われるかというと、**発射玉が前に割り込むか後ろに割り込むか**
の判定です(章09)。

【GIF: rail/binary-search.gif】
  d = 1200 を探す。lo と hi の範囲が半分ずつ狭まっていき、
  最後に隣り合う2点になって、その間を線形補間して座標が出る。


## 4-8 posAt と posAtInto の使い分け

  js/rail.js:272
    function posAt(d) { return posAtInto(d, {}); }

同じ計算をする関数が2つあります。違いは **戻り値のオブジェクトを毎回作るかどうか**。

posAt は毎回 {} を新しく作ります。使いやすいですが、
毎フレーム 100 回呼ぶと 1 秒で 6000 個のオブジェクトが生まれて捨てられます。
これは JavaScript のガベージコレクタ(不要メモリの掃除係)の仕事を増やし、
たまにカクつきの原因になります。

posAtInto は呼び出し側が用意したオブジェクトに書き込むだけなので、
新しいオブジェクトを作りません。

  js/main.js:19
    var _pos = { x: 0, y: 0, tx: 0, ty: 0 };

main.js はモジュールの外側に1個だけ _pos を持ち、毎回それを使い回します。

  js/main.js:261
    var p = rail.posAtInto(Math.max(vd, 0), _pos);

同じ工夫は cannon.js:102 と course-view.js:19 にもあります。

  使い分けの原則:
    毎フレーム何十回も呼ぶ場所 → posAtInto + 使い回しオブジェクト
    たまにしか呼ばない場所     → posAt(読みやすさ優先)


## 4-9 自己交差の検出

コース1(橋を渡る道)は1本の道が自分自身と交差します。
そこを「立体交差」にするには、どこで交差しているかを知る必要があります。

まず線分どうしの交差判定から。

  js/rail.js:98-105
    function segHit(x1, y1, x2, y2, x3, y3, x4, y4) {
      var d = (x2 - x1) * (y4 - y3) - (y2 - y1) * (x4 - x3);
      if (d === 0) return -1;            // 平行
      var s = ((x3 - x1) * (y4 - y3) - (y3 - y1) * (x4 - x3)) / d;
      var t = ((x3 - x1) * (y2 - y1) - (y3 - y1) * (x2 - x1)) / d;
      if (s < 0 || s >= 1 || t < 0 || t >= 1) return -1;
      return t;
    }

線分1を P1→P2、線分2を P3→P4 とします。
それぞれの上の点は次のように書けます。

  線分1上の点 = P1 + s × (P2 - P1)    (0 ≤ s ≤ 1)
  線分2上の点 = P3 + t × (P4 - P3)    (0 ≤ t ≤ 1)

この2つが等しくなる s と t を求める、というのが交差判定です。
連立方程式を解くと上の式になります。

  d は「2つの線分の向きの外積」で、0 なら平行(交わらない)。
  s も t も 0〜1 の範囲に入っていれば、線分の内部で交わっている。

範囲チェックが `s >= 1` と「半開区間 [0, 1)」になっているのには理由があります。

  js/rail.js:92-97 のコメント:
    「直角の街路では交差点が片方の道の頂点にちょうど乗ることが多く、
      端点を両側とも弾くと(t=0 と t=1 の隣接2セグメント両方で落ちて)
      検出漏れになる。半開なら頂点に乗る交差を『そこから始まる側』で
      1回だけ拾える。」

つまり [0, 1] にすると同じ交差を2回拾い、(0, 1) にすると0回になる。
[0, 1) にすると、ちょうど1回になります。

次に、全セグメント対を総当たりします。

  js/rail.js:41-62
    function findIntersections(aXs, aYs, aCum, bXs, bYs, bCum, self) {
      var out = [];
      var MIN_GAP = PP.D * 4;
      var na = aXs.length - 1, nb = bXs.length - 1;
      for (var i = 0; i < na; i++) {
        var ax = aXs[i], ay = aYs[i], bx = aXs[i + 1], by = aYs[i + 1];
        for (var j = self ? i + 2 : 0; j < nb; j++) {
          if (self && bCum[j] - aCum[i] < MIN_GAP) continue;
          var t = segHit(ax, ay, bx, by, bXs[j], bYs[j], bXs[j + 1], bYs[j + 1]);
          if (t < 0) continue;
          ...
        }
      }
      return out;
    }

自己交差(self = true)のときの工夫が2つ。

  ・j を i+2 から始める … 隣り合うセグメントは端点を共有しているので、
                          必ず「交差」してしまう。それは交差ではない。
  ・MIN_GAP = D*4 のチェック … 弧長で 192px 未満しか離れていない対も無視。
                          カーブの内側では、少し離れたセグメントどうしが
                          数値誤差でかすったように判定されることがある。

自己交差でないとき(レーンAとレーンBの交差)は、j を 0 から回して全部見ます。

見つかった交差点から「上になる区間」を作ります。

  js/rail.js:66-72
    function detectCrossings(xs, ys, cum) {
      var out = [];
      var W = PP.D * 1.5;                 // 交差点の前後この距離を「上」にする
      var hits = findIntersections(xs, ys, cum, xs, ys, cum, true);
      for (var i = 0; i < hits.length; i++) out.push([hits[i].db - W, hits[i].db + W]);
      return out;
    }

db は「2本目(自分自身)の側の弧長」。つまり **後から通る側** です。
その前後 72px を「上」の区間とします。

「後から通る側が上」というのは、階段を上って橋を渡るイメージです。
自己交差なら常にこのルールで一意に決まります。

【GIF: rail/self-intersection.gif】
  折れ線のセグメント対を総当たりでスキャン(i, j のループが光る)。
  交差が見つかると db ± D*1.5 の帯が「上」として塗られ、
  そこを通る玉が ballOver レイヤーへ移る。


## 4-10 heightAt と tunnelAt

  js/rail.js:281-287
    function heightAt(d, pad) {
      pad = pad || 0;
      for (var i = 0; i < overIntervals.length; i++) {
        if (d >= overIntervals[i][0] - pad && d <= overIntervals[i][1] + pad) return 1;
      }
      return 0;
    }

d がどれかの「上区間」に入っていれば 1(上)、なければ 0(下)。
overIntervals はコース1では自動検出、コース2/5 では作者が raised で指定したもの。
両方あれば連結されます。

  js/rail.js:245-247
    var overIntervals = (course && course.overpass) ? detectCrossings(xs, ys, cum) : [];
    var raised = raisedOf(course, laneIndex, length);
    if (raised.length) overIntervals = overIntervals.concat(raised);

pad 引数が面白いところです。コメント(js/rail.js:276-280)を読むと:

  「区間をそのまま(pad=0)使うと、玉の中心が hi を過ぎた瞬間に
    ballOver → ballUnder へ移るが、玉には半径があるので前半分はまだ
    桁の上に乗っている。結果、橋の出入り口で玉が桁に食い込んで欠けて見える。
    『玉が桁に少しでも重なっている間は上の層に置く』= pad=R が正しい。」

だから描画では pad = R を渡し、

  js/main.js:304
    var target = lane.rail.heightAt(vd, PP.R) > 0 ? PP.layers.ballOver : PP.layers.ballUnder;

当たり判定では pad なしで呼びます。

  js/cannon.js:537
    bover[k] = lane.rail.heightAt(balls[k].d) > 0;

【GIF: rail/height-tunnel.gif】
  左: pad=0 だと橋の出口で玉が桁に半分欠ける
  右: pad=R だと最後まで上に乗って見える
  下段でトンネル区間に入った玉が visible=false になる様子も。

トンネルはもっと単純です。

  js/rail.js:290-295
    function tunnelAt(d) {
      for (var i = 0; i < tunnels.length; i++) {
        if (d >= tunnels[i][0] && d <= tunnels[i][1]) return true;
      }
      return false;
    }

区間の中なら true。描画側は玉を非表示にし、

  js/main.js:284
    b.view.visible = vd > -PP.R && !rail.tunnelAt(vd);

大砲側は当たり判定から外します(= 撃てない)。

  js/cannon.js:599
    if (c.btun[i]) continue;  // トンネル内=隠れていて撃てない

トンネルの中でも物理(前進・磁力・マッチ)は動き続けます。
見えないところで消えたり進んだりする、という戦略的な盲点になります。

## 5-1 玉は3枚のBitmapでできている

  js/ball.js:125-136 の makeView() が返すのは Container で、中身は3枚。

    base   下地(色)+ リムライト + フレネル発光 を1枚に焼いたもの
    spin   塗装の合わせ目と傷(これだけが回転する)
    shade  陰影・スペキュラ・輪郭(固定)

順番が大事です。spin(回転する模様)を、shade(固定の光)より **下** に置く。
これで「玉が回っているが、光の当たり方は変わらない」= 転がって見えます。

もし shade も一緒に回すと、光源ごと回ってしまい「玉が自転している」ではなく
「玉ごとカメラが回っている」ように見えます。


## 5-2 焼き込み(bake)の最適化

  js/ball.js:36-38
    var CB = R + 2, CS = (R + 2) * 2;          // cache 範囲(中心が原点)
    var baseCanvas = [], shadeCanvas = [];     // 色ごと
    var spinCanvas = null;                     // 色に依らず共通

配列で「色ごとに1枚」持ちます。初めてその色の玉を作るときだけ焼きます。

  js/ball.js:126-127
    if (baseCanvas[colorIndex] === undefined) bakeColor(colorIndex);
    if (!spinCanvas) bakeSpin();

これを「遅延初期化(lazy initialization)」と呼びます。
6色ぜんぶ最初に焼く必要はなく、実際に出た色だけ焼けば十分です。

  js/ball.js:41-44
    function bake(disp) {
      disp.cache(-CB, -CB, CS, CS);
      return disp.cacheCanvas;
    }

cache 範囲は (-26, -26) から 52×52。玉の半径 24 に対して +2 の余白があるのは、
輪郭線(setStrokeStyle(1.5))が切れないようにするためです。

  js/ball.js:48-51
    function sprite(canvas) {
      var b = new createjs.Bitmap(canvas);
      b.regX = b.regY = CB;
      return b;
    }

同じ canvas を何枚もの Bitmap が共有します。canvas 自体は1つなので、
赤い玉が 50 個あってもメモリ上の画像は1枚です。


## 5-3 base に3層を焼き込む理由

  js/ball.js:56-86 の bakeColor() は、base コンテナに3つの Shape を入れて焼きます。

    body  放射状グラデーション(色そのもの)
    rim   下端の色付きリムライト(alpha 0.28)
    fres  縁のフレネル発光(compositeOperation = "lighter", alpha 0.5)

  js/ball.js:85-86
    base.addChild(body, rim, fres);
    baseCanvas[colorIndex] = bake(base);

コンテナごと cache すると、CreateJS は子の alpha と compositeOperation を
反映した状態で1枚に焼きます。つまり **加算合成の計算が焼くとき1回だけ**。

もし焼かずにステージ上で重ねると、玉 100 個 × 加算合成の Shape 1枚 =
毎フレーム 100 回の加算合成ブリットが走ります。焼き込めば 0 回です。

ここで「なぜ spin だけ別なのか、なぜ shade も焼き込まないのか」ですが、

  ・spin は回転する → 焼き込めない(回転角が毎フレーム変わる)
  ・shade は spin の**上**にある → 焼き込むと spin が隠れる

だから「spin より下の静止層(body/rim/fres)は1枚に」「spin より上の静止層
(shade)はもう1枚に」という3枚構成が最小になります。

コメント(js/ball.js:26-33)には、この焼き込みが見た目を変えない理由も
書いてあります。

## 5-4 回転の計算 SPIN_K

  js/ball.js:17
    PP.SPIN_K = 180 / (Math.PI * R);

  js/main.js:282
    if (b.view.spin) b.view.spin.rotation = vd * PP.SPIN_K;

「レール上を vd px 進んだら、何度回るか」の係数です。

転がる球は「進んだ距離 = 円周上の弧の長さ」になります。

  進んだ距離 vd = 半径 R × 回転角(ラジアン)
  → 回転角(ラジアン) = vd / R
  → 回転角(度)      = vd / R × 180 / π = vd × 180 / (π R)

だから SPIN_K = 180 / (π × 24) ≒ 2.387。
1px 進むと約 2.39 度回ります。玉1個ぶん(48px)進むと約 114.6 度。

CreateJS の rotation は度(degree)なので、ラジアンから度に直しています。

発射玉のほうは符号が逆です。

  js/cannon.js:576
    sh.view.spin.rotation = -sh.roll * PP.SPIN_K;

上に飛ぶ玉は逆回転に見えるほうが自然なので、マイナスを付けています。


## 5-5 宝玉と爆弾

宝玉は makeTreasureView()(js/ball.js:191-220)。

  glow  外側の光(ふわっと脈打つ)
  orb   金のオーブ(cache 済み)
  gem   💎 の絵文字(cache 済み)

光る演出は Tween のループです。

  js/ball.js:215-217
    createjs.Tween.get(glow, { loop: true })
      .to({ alpha: 0.25, scaleX: 0.85, scaleY: 0.85 }, 550, createjs.Ease.quadInOut)
      .to({ alpha: 1, scaleX: 1.15, scaleY: 1.15 }, 550, createjs.Ease.quadInOut);

{ loop: true } で永久にループします。だから宝玉を消すときは、
必ず Tween を止めてから removeChild しないと、参照が残り続けます。

  js/chain.js:533-538
    function removeTreasureAt(lane, index) {
      var t = lane.balls.splice(index, 1)[0];
      createjs.Tween.removeTweens(t.view.glow);
      if (t.view.parent) t.view.parent.removeChild(t.view);
      return t;
    }

爆弾 makeBombView()(js/ball.js:139-188)も同様に、導火線の火花が
ループ Tween で脈打っています。撃ったり画面外に出たりしたときは

  js/cannon.js:580
    if (sh.view.spark) createjs.Tween.removeTweens(sh.view.spark);

で止めています。**ループ Tween は明示的に止める** — これは覚えておく価値のある
CreateJS の作法です。
