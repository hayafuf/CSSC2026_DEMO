## 6-1 設計思想: 原作 Zuma と同じ「後ろから押される1本の列」

ファイル冒頭のコメント(js/chain.js:16-25)がこのファイルの憲法です。

  ・進むのは最後尾グループ(補給口に押されている側)と、宝玉を連れている
    グループ。宝玉のない分断グループは、後続が接触して合流するまで完全に停止する。
  ・速度はレール上の位置で決まる(speedAt)。洞窟から出た直後は速く、
    樽に近づくほど少しずつ減速する。
  ・隙間は同色なら磁力で閉じる。ぶつけた側のグループが洞窟方向へ押し戻される。
  ・重なりは後ろ→前への押し出しで解決。

ここで一番わかりにくいのが最初の1行です。順を追って説明します。

  チェーンが途中で消えて、こうなったとする(左が樽側、右が洞窟側):

    ●●●●●     [すきま]     ●●●●●●●●
    前グループ              後グループ(最後尾)

  「後ろから押されている」のは後グループだけです。だから **後グループだけが進み、
   前グループは完全に止まります**。玉に慣性はありません。

これは現実の物理とは違いますが、ゲームとして正しい挙動です。
前グループも一緒に進むと、消しても消しても前線が下がらず、詰みます。
逆に前グループが止まってくれるので、「消す = 時間を稼ぐ」が成立します。

  【GIF: chain/advance-groups.gif】
    チェーンが2つに分断され、後ろだけが進んで隙間が縮まり、
    接触した瞬間に1つのグループとして動き出す。


## 6-2 マッチ判定は「イベント駆動」

もうひとつ重要な設計判断が、コメント(js/chain.js:24-26)にあります。

  「マッチ判定は原作 Zuma と同じくイベント駆動:
    発射玉の割り込み・磁力の合流・消したあとの接合のときだけ調べる。」

これは何を意味するか。

  洞窟から ●●●● と同じ色が4個並んで出てきても、**消えません**。

もし毎フレーム全部の玉を調べて「3個以上並んでいたら消す」としたら、
補給の段階で勝手に消えてしまい、ゲームになりません。

だから調べるのは、次の3つのタイミングだけです。

  ① 発射した玉が割り込んだあと(insertShot → pendingMatches)
  ② 分断されていた接合点が閉じたとき(snapshotJoints → resolveJoints)
  ③ 玉を消した直後、その跡の前後が接触していたとき(joinAt)

この方針のおかげで、ball.js の spawnColor は安心して同色を並べられます
(章10)。


## 6-3 update(dt) — フレームの入り口

  js/chain.js:206-228
    function update(dt) {
      var g = PP.game;
      var eff = g.effects;

      // レベル開始のなだれ込み
      if (g.rolloutBoost > 0) {
        g.rolloutBoost *= Math.exp(-dt / PP.ROLLOUT_DECAY);
        if (g.rolloutBoost < 0.05) { g.rolloutBoost = 0; g.rolloutDone = true; }
      }

      // 逆風の風速(全レーン共通なのでここで1回だけ更新)
      if (eff.reverse > 0) {
        if (!reverseWasActive) reverseV = PP.REVERSE_SPEED;
        var windMax = speedAt(g.lanes[0], 0) + PP.REVERSE_MARGIN;
        reverseV = Math.min(reverseV + PP.REVERSE_ACCEL * dt, windMax);
      }
      reverseWasActive = eff.reverse > 0;

      for (var li = 0; li < g.lanes.length; li++) {
        updateLane(g.lanes[li], dt);
      }
    }

「全レーン共通のもの」をここで先に処理し、そのあとレーンごとの処理へ入る、
という2段構えです。

rolloutBoost は「レベル開始直後だけ玉がなだれ込む」演出の倍率です。

  js/main.js:109
    g.rolloutBoost = 1;      // 開始直後だけ速く流れ込み、減衰して通常速度へ

  js/config.js:39-40
    PP.ROLLOUT_BOOST = 2.2;  // なだれ込み加算倍率
    PP.ROLLOUT_DECAY = 0.5;  // 減衰時定数(秒)

Math.exp(-dt / 0.5) を毎フレーム掛けるので、0.5 秒で 37%、1秒で 14%、
1.5秒で 5% を切って 0 になります。そのとき rolloutDone = true になり、
生存ゲージが減り始めます(main.js:208)。

  演出上の効果:
    レベル開始 → 玉が「ざーっ」と勢いよく流れ込んでくる → 1〜2秒で通常速度
    → ここからが本番、というリズムが作れる。

風速 reverseV も同じ形です。発動の瞬間に初速 200、そこから 340 px/s² で加速。
上限は「洞窟側の進行速度 + 180」です。

  var windMax = speedAt(g.lanes[0], 0) + PP.REVERSE_MARGIN;

固定値ではなく speedAt(0) に連動させているのがポイントで、
レベルが上がってチェーンが速くなっても、必ず風のほうが勝つようになります。


## 6-4 updateLane(lane, dt) — レーン1本の6フェーズ

  js/chain.js:233-252
    function updateLane(lane, dt) {
      updateWaveTimer(lane, dt);
      spawnBalls(lane);

      if (lane.balls.length > 0) {
        var starts = groupStarts(lane);
        var joints = snapshotJoints(lane, starts);

        advance(lane, dt, starts);     // 1) 前進
        applyRecoil(lane, dt);         // 2) 反動
        applyMagnet(lane, dt, starts); // 3) 磁力
        relax(lane, false);            // 4) 重なり解消
        resolveJoints(lane, joints);   // 5) 閉じた接合のマッチ判定
      }

      updateTreasures(lane);
      updateAnims(lane, dt);
      updatePendingMatches(lane, dt);
    }

順番に意味があります。

  ・玉の増減が起きるのは spawnBalls だけ。そのあと starts(グループの区切り)を
    1回計算して、1〜5 で使い回す。途中で玉が増えたら starts がずれてしまう。
  ・joints は「移動する前の隙間」を記録しておくためのもの。移動したあとに
    「さっきまで空いていた隙間が閉じたか?」を調べる材料になる。
  ・重なり解消(relax)は最後。前進・反動・磁力で玉がめり込むことがあるので、
    それを最後にまとめてほどく。

そこにレールの長さで補正がかかります。

  var scale = Math.max(0.35, Math.min(1, lane.rail.length / PP.WAVE_REF_LEN));

  js/config.js:139

コース0(全長 約8700px)なら scale = 1 でそのまま。
コース3(四叉の激流)はレーンが短いので scale が小さくなり、玉数が減ります。

「長さに比例した密度にする」という正規化です。

needTreasure は「この波の最後に宝玉を付けるべきか」のフラグ。
waveFresh は「まだこの波の1個目を出していない」フラグ。

### updateWaveTimer — 次の波のタイミング

  js/chain.js:74-83
    function updateWaveTimer(lane, dt) {
      var g = PP.game;
      if (g.state !== "playing" || g.finishing) return;
      if (lane.waveTimer > 0) lane.waveTimer -= dt;
      if (lane.pending > 0 || lane.needTreasure) return;
      var balls = lane.balls;
      var clear = balls.length === 0 || balls[balls.length - 1].d >= D;
      if (!clear) return;
      if (lane.waveTimer <= 0 || balls.length === 0) startWave(lane);
    }

条件が3段階になっています。

  ① g.finishing なら何もしない(掃討フェーズ = 補給打ち切り)
  ② 前の波がまだ出し終わっていない(pending > 0 か needTreasure)なら待つ
  ③ 最後尾の玉が洞窟口(d = D = 48)より先へ進んでいないと出せない
     → 出口に玉が詰まっている状態で次を出すと重なる

そして「時間が来た」か「そもそも玉が1個もない」なら次の波へ。

while ループの条件が肝です。

  balls[balls.length - 1].d >= D

「最後尾の玉が洞窟口から玉1個ぶん以上進んでいれば、次を置ける」。
つまり **玉は詰まるまでしか出ない**。玉が進めば進んだぶんだけ、
自動的に後ろから供給される、という自然な流れになります。

新しく置く玉の d は、最後尾の玉の d から D を引いた値。
つまり **最後尾のさらに 48px 後ろ**。d が負になることもあります(画面外の洞窟の中)。

  d が負の玉は非表示になります(js/main.js:284):
    b.view.visible = vd > -PP.R && ...

新しい波の1個目だけは d = 0 に置きます(waveFresh の分岐)。
前の波が遠くまで進んでいても、新しい波は必ず洞窟口から始まります。

波の補給が終わったら、末尾に宝玉を追加します。

宝玉は color: null、treasure: true を持ちます。
color が null なので、色のマッチ判定には絶対に引っかかりません。

## 6-6 groupStarts — グループの区切りを見つける

  js/chain.js:122-129
    function groupStarts(lane) {
      var balls = lane.balls;
      var starts = [0];
      for (var i = 1; i < balls.length; i++) {
        if (balls[i - 1].d - balls[i].d > D + 0.5) starts.push(i);
      }
      return starts;
    }

balls[0] が先頭(樽に一番近い、d が最大)、末尾が最後尾(d が最小)です。
だから balls[i-1].d - balls[i].d は **前の玉と自分の距離** で、常に正のはず。

それが D + 0.5 = 48.5 より大きければ「隙間が空いている」= 新しいグループの開始。

  balls: [d=1000, d=952, d=904, d=800, d=752]
                              ↑ 904 - 800 = 104 > 48.5 なので区切り
  starts = [0, 3]

  グループ1 = balls[0..2]  (先頭側)
  グループ2 = balls[3..4]  (最後尾)

starts には「各グループの開始インデックス」だけが入ります。
グループの終わりは「次の starts」または「配列の末尾」です。
この形はコード中で繰り返し出てきます。

  var gs = starts[si];
  var ge = (si + 1 < starts.length) ? starts[si + 1] : balls.length;
  // balls[gs] 〜 balls[ge-1] が1グループ

## 6-7 speedAt — 位置で決まる速度

  js/chain.js:147-156
    function speedAt(lane, d) {
      var g = PP.game;
      var t = Math.max(0, Math.min(1, d / lane.rail.holeD));
      var v = PP.SPEED_HOLE +
              (PP.SPEED_ENTRY - PP.SPEED_HOLE) * Math.pow(1 - t, PP.SPEED_CURVE);
      v *= 1 + (g.level - 1) * PP.LEVEL_SPEED;      // レベルで底上げ
      v *= 1 + PP.ROLLOUT_BOOST * g.rolloutBoost;   // 開始直後のなだれ込み
      if (g.effects.slow > 0) v *= 0.5;
      return v;
    }

t は 0(洞窟)〜1(樽)の進み具合。Math.max/min で 0〜1 にクランプしています
(d が負や holeD 超えのことがあるため)。

基本の速度カーブ:

  v = 18 + (600 - 18) × (1 - t)^1.8

  t=0.0 → 18 + 582 × 1.000 = 600 px/s
  t=0.2 → 18 + 582 × 0.674 = 410 px/s
  t=0.4 → 18 + 582 × 0.418 = 261 px/s
  t=0.6 → 18 + 582 × 0.221 = 147 px/s
  t=0.8 → 18 + 582 × 0.076 =  62 px/s
  t=1.0 → 18 +   0         =  18 px/s

指数 1.8 が「後半でぐっと落ちる」形を作ります。
1.0(直線)だと減速が単調で、2.5 だと最初から遅くなりすぎます。

そこに3つの倍率がかかります。

  レベル補正   1 + (level-1) × 0.06   レベル10 なら ×1.54
  なだれ込み   1 + 2.2 × rolloutBoost 開始直後は最大 ×3.2
  スロー効果   slow > 0 なら ×0.5

  【GIF: chain/speed-at.gif】
    上段: 速度カーブのグラフ(横軸 t、縦軸 v)。現在位置のマーカーが動く。
    下段: 実際のレール上で玉が進む。洞窟側では速く、樽側でゆっくりになる。
    LEVEL_SPEED と slow のトグルで曲線が上下する。

### 逆風モード

  js/chain.js:280-286
    for (var ri = 0; ri < starts.length; ri++) {
      var rs = starts[ri];
      var re = (ri + 1 < starts.length) ? starts[ri + 1] : balls.length;
      var net = Math.min(0, speedAt(lane, balls[rs].d) - reverseV) * dt;
      if (net === 0) continue;
      for (i = rs; i < re; i++) balls[i].d += net;

「正味速度 = 進もうとする速度 - 風速」。Math.min(0, ...) で頭打ちにするので、
風がまだ弱いうちは 0(止まる)、風が勝てば負(後退)になります。

前進はしません。「逆風なのに前に進んだ」では効果が分からないからです。

グループごとに **同じ量** 動かすので、グループ内の間隔は崩れません。

ループが **後ろから前へ**(si = starts.length-1 → 0)なのに注目してください。
最後尾グループを最初に処理します。

そして continue の条件が、6-1 で説明した「動くのは誰か」の実装です。

  「最後尾グループではない」かつ
  (「宝玉を含まない」または「宝玉1個だけ」)なら → 動かさない

つまり動くのは:

  ・最後尾グループ(補給に押されている)
  ・宝玉を含むグループ(ただし宝玉1個だけの場合を除く)

宝玉を連れているグループが自力で進むのは、後続の波に置いていかれないためです
(README にも書かれている仕様)。
宝玉1個だけのときは「磁石」になるので前進しません(章07 で扱います)。

  js/chain.js:132-143
    function hasTreasure(lane, start, end) {
      for (var i = start; i < end; i++) {
        if (lane.balls[i].treasure) return true;

      return false;

    function isLoneTreasure(lane, start, end) {
      return end - start === 1 && !!lane.balls[start].treasure;

### 速度の基準位置 spdD

  js/chain.js:296-315
    var head = balls[gs];
    var ref = head.spdD;
    var hold = head.spdHold || 0;
    if (ref === undefined || head.d >= ref) {
      ref = head.d;                       // 通常の前進(基準は先頭そのもの)
      hold = PP.SPD_REF_HOLD;
    } else if (recIdx >= gs && recIdx < ge) {
      hold = PP.SPD_REF_HOLD;             // 反動中は据え置き
    } else if (hold > 0) {
      hold -= dt;                         // 分断直後の猶予
    } else {
      ref = head.d + (ref - head.d) * Math.exp(-dt / PP.SPD_REF_RELAX);
    }
    var step = speedAt(lane, ref) * dt;
    for (i = gs; i < ge; i++) {
      balls[i].d += step;
      balls[i].spdD = ref;
      balls[i].spdHold = hold;
    }

ここは一見複雑ですが、解こうとしている問題は明確です。

  【問題】
  チェーンの真ん中が消えて分断されると、後ろの断片は「消える前の先頭」の
  位置(樽寄り = 遅い速度)を基準に持ったままになる。
  それを引きずると、洞窟のすぐそばにいる断片が樽の直前の速さで這うことになる。

  でも即座に「自分の新しい先頭」の速度に切り替えると、
  分断の瞬間に断片がガクンと加速して見える。

  【解決】
  少し待ってから、じわりと自分の先頭へ寄せ直す。

そのための2つの定数です。

  js/config.js:46-47
    PP.SPD_REF_HOLD = 0.45;  // 追従を始めるまでの猶予(秒)
    PP.SPD_REF_RELAX = 0.9;  // 基準が自分の先頭へ寄る時定数(秒)

分岐を順に読むと:

  ① ref が未定義、または head.d >= ref(自分が基準に追いついた)
     → 普通に進んでいる。基準は自分自身。hold をリセット。
  ② 反動中(このグループが押し戻されている)
     → 基準を据え置く。弾き飛ばしたご褒美を加速で帳消しにしない。
  ③ hold > 0(分断してから 0.45 秒たっていない)
     → 何もしない。hold を減らす。
  ④ それ以外
     → 指数減衰で ref を head.d へ近づける。0.9 秒の時定数でゆっくり。

そして速度は speedAt(lane, ref)。head.d ではなく ref で計算するのがミソです。

## 7-1 磁力とは何か

チェーンが分断されて隙間ができたとき、**隙間の前後の玉が同じ色なら**、
前のグループが後退して隙間を埋めにいきます。これが磁力(magnet / attract)です。

  ●●●[赤]    [すきま]    [赤]●●●●●
      ↑ 前グループの最後尾      ↑ 後グループの先頭
       ←←← こちらが後退して埋める

なぜこの仕様なのか。**これが連鎖(コンボ)の主要な発生源** だからです。

プレイヤーが狙って「消したあとに同じ色が向かい合う」ように仕込むと、
自動で合流 → 3個以上そろって消える → また向かい合う → ... と連鎖します。
運ではなく腕で起こせるので、上手さの報酬になります。

  【GIF: chain/magnet-rewind.gif】
    ★ 最重要 GIF。
    同色の隙間 → 前グループが v=250 から加速しながら後退 →
    合流 → 3個そろって消滅 → 跡の前後がまた同色 → 連鎖。
    速度メーター(250 → 640 px/s)と gap の数値を同時表示。

## 7-3 引き合うかどうかの判定

  js/chain.js:330-342

    var headLone = balls[head].treasure &&

判定は2種類あります。

【通常の磁力(attract)】
  ・どちらも宝玉ではない
  ・色が同じ
  → 引き合う

【宝単体の磁石(magnet)】
  ・後グループの先頭が宝玉で、それが1個だけ(次の玉と離れている)
  ・前グループの最後尾は宝玉ではない
  → 色に関係なく引き合う

宝単体の磁石は README にある特殊ルールです。

  「宝玉が1個だけ取り残されたときは前進をやめ、磁石になります。
    色に関係なく前(樽側)のチェーンを引き戻して自分に合流させるので、
    宝を守るほどチェーンが樽から遠ざかります。」

つまり「宝を守るほど有利になる」という報酬設計です。

hitCd(不応期)のチェックも重要です。

## 7-4 磁力が切れたときの慣性(coast)

  js/chain.js:343-358
    if (!attract || gap <= 0) {
      var coast = balls[tail].pull || 0;
      if (coast <= 0 || gap <= 0) {
        if (gap <= 0 && attract && !magnet && coast > 0) impact(lane, head, coast);
        for (i = gStart; i <= tail; i++) balls[i].pull = 0;
        continue;
      }
      coast *= Math.exp(-dt / PP.COAST_DECAY);
      if (coast < PP.COAST_MIN) coast = 0;
      var coastMove = Math.min(coast * dt, gap);
      for (i = gStart; i <= tail; i++) {
        balls[i].d -= coastMove;
        balls[i].pull = coast;
      }
      continue;
    }

これは「磁力が途中で切れたときに急停止させない」ための処理です。

シナリオ:
  1. 赤と赤が引き合って、前グループが 640 px/s で巻き戻っている
  2. 合流して3個そろって消える
  3. 新しく向かい合った色が違う → 磁力オフ

このとき急に止まったら「連鎖が切れた」感じが強すぎます。
そこで pull(いまの巻き戻り速度)を保ったまま、指数減衰で滑らせます。

  js/config.js:60-61
    PP.COAST_DECAY = 0.5;   // 時定数(秒)
    PP.COAST_MIN = 25;      // これ以下で止める px/s

コメント(js/config.js:58)に効果が書かれています。

  「コンボの勢い(最大 640px/s)なら 玉9個ぶん ≒ 300px 滑る、大きなご褒美。」

滑る距離はおよそ「速度 × 時定数」= 640 × 0.5 = 320px。
玉6〜7個ぶん前線が下がるので、体感でかなり助かります。

逆に「磁力が働いていない単発の消去」では pull が 0 なので巻き戻りません。
連鎖したときだけのご褒美になっています。


## 7-5 引き寄せの加速

  js/chain.js:359-371
    var v0 = magnet ? PP.MAGNET_SPEED : PP.ATTRACT_SPEED;
    var acc = magnet ? PP.MAGNET_ACCEL : PP.ATTRACT_ACCEL;
    var vmax = magnet ? PP.MAGNET_MAX : PP.ATTRACT_MAX;
    if (magnet) {
      var near = Math.max(0, 1 - gap / PP.MAGNET_RANGE);
      acc *= 1 + PP.MAGNET_NEAR_GAIN * near * near;
    }
    var v = Math.min(Math.max(balls[tail].pull || 0, v0) + acc * dt, vmax);
    var pullMove = Math.min(v * dt, gap);
    for (i = gStart; i <= tail; i++) { balls[i].d -= pullMove; balls[i].pull = v; }

通常の磁力と宝単体の磁石で、パラメータが違います。

              初速  加速度  最高速
  通常(attract)  250   1300    640
  宝単体(magnet)  10    260     430

宝単体は「ほぼ静止からじわりと動き出す」ようにしてあります。
そして近づくほど加速が増します。

  var near = Math.max(0, 1 - gap / PP.MAGNET_RANGE);   // 0(遠い)〜1(密着)
  acc *= 1 + PP.MAGNET_NEAR_GAIN * near * near;         // 最大 ×3.5

  js/config.js:91-92
    PP.MAGNET_RANGE = 300;       // この距離まで縮むと加速が増し始める px
    PP.MAGNET_NEAR_GAIN = 2.5;   // 密着直前の加速度の増し方

near を2乗しているので、遠いうちはほとんど効かず、近づくと急に強くなります。
「磁石にすっと吸い付く」感触の再現です。

速度の更新式:

  var v = Math.min(Math.max(balls[tail].pull || 0, v0) + acc * dt, vmax);

  Math.max(前フレームの速度, 初速)  ← 勢いを引き継ぐ。ただし初速は下回らない
  + acc * dt                        ← 加速
  Math.min(..., vmax)               ← 頭打ち

移動量は `Math.min(v * dt, gap)`。**隙間より大きくは動かない** ので、
行き過ぎてめり込むことがありません。

衝突の勢い v を、後ろの列を押し戻す速度 rv に変換します。

  rv = v × ratio × mult

  通常     ratio 0.5、mult 1     → 640 × 0.5 = 320 px/s
  コンボ中 ratio 0.8、mult 最大2.5 → 640 × 0.8 × 2.5 = 1280 px/s

### willMatchAt — 先読み

  js/chain.js:404-420
    function willMatchAt(lane, headIndex) {
      var balls = lane.balls;
      var front = balls[headIndex - 1], back = balls[headIndex];
      if (!front || !back) return false;
      var c = front.color;
      if (c === null || c === undefined || back.color !== c) return false;
      var n = 0, i;
      for (i = headIndex - 1; i >= 0 && balls[i].color === c; i--) {
        if (i < headIndex - 1 && balls[i].d - balls[i + 1].d > D + 1) break;
        n++;
      }
      for (i = headIndex; i < balls.length && balls[i].color === c; i++) {
        if (i > headIndex && balls[i - 1].d - balls[i].d > D + 1) break;
        n++;
      }
      return n >= 3;
    }

「いま繋がったとして、同色3個以上になるか?」を **消す前に** 調べます。

なぜ先読みが必要か。impact はマッチ判定より前に呼ばれるので、
その時点の g.combo はまだ更新されていません。だから「この衝突が
コンボを1段進めるものかどうか」を自前で判断する必要があります。

コードは headIndex から左右に同色を数えるだけです。
途中で隙間(> D + 1)があったら break します。

### 反動の置き換え判定

  js/chain.js:424
    function recoilReach(v, damp, max, moved) {
      return Math.min(v / damp, Math.max(0, max - (moved || 0)));
    }

  js/chain.js:449-457
    var replaced = false;
    if (!lane.recoil ||
        recoilReach(rv, damp, maxDist, 0) >
        recoilReach(lane.recoil.v, lane.recoil.damp || PP.RECOIL_DAMP,
                    lane.recoil.max, lane.recoil.moved)) {
      lane.recoil = { anchor: anchor, v: rv, moved: 0, max: maxDist, damp: damp };
      replaced = true;
    }
    if (!replaced && lane.recoil.anchor === anchor) return;

同じフレームで複数の衝突が起きたり、連鎖で反動が続いたりします。
そのとき「どっちの反動を採用するか」を、**あとどれだけ押せるか** で比べます。

  v / damp     指数減衰で止まるまでの距離(∫ v·e^(-damp·t) dt = v/damp)
  max - moved  上限までの残り

その小さいほうが「実際に押せる距離」。大きいほうを採用します。

単に速度で比べると、「速いけどもう上限まで押し切った反動」が
「遅いけどまだ余裕がある反動」に勝ってしまい、実際には動かなくなります。


## 7-8 applyRecoil — 反動を適用する

  js/chain.js:477-504
    function applyRecoil(lane, dt) {
      var balls = lane.balls;
      var rec = lane.recoil;
      if (!rec) return;
      var ai = balls.indexOf(rec.anchor);
      if (ai < 0) { lane.recoil = null; return; }

      if (!rec.inherited) {
        rec.anchor.hitCd = PP.BOUNCE_COOLDOWN;
        if (balls[ai - 1]) balls[ai - 1].hitCd = PP.BOUNCE_COOLDOWN;
      }

      var start = ai;
      while (start > 0 && balls[start - 1].d - balls[start].d <= D + 0.5) start--;
      var end = ai + 1;
      while (end < balls.length && balls[end - 1].d - balls[end].d <= D + 0.5) end++;

      var step = Math.min(rec.v * dt, rec.max - rec.moved);
      step = Math.min(step, balls[end - 1].d - PP.RECOIL_FLOOR);
      if (step > 0) {
        for (var i = start; i < end; i++) balls[i].d -= step;
        rec.moved += step;
      }
      rec.v *= Math.exp(-(rec.damp || PP.RECOIL_DAMP) * dt);
      if (rec.v < 8 || rec.moved >= rec.max) lane.recoil = null;
    }

anchor(ぶつけられた玉)を **玉の参照** で持っているのがポイントです。
インデックスで持つと、玉が消えたときにずれてしまいます。

  if (ai < 0) { lane.recoil = null; return; }   // anchor が消えたら反動も終わり

押し戻す範囲は「anchor を含む接触している連続区間」を左右に伸ばして決めます。
starts を使わずにその場で調べているのは、reccoil が適用される時点で
グループの構成が変わっている可能性があるからです。

洞窟の奥へ押し込みすぎない安全弁もあります。

  js/config.js:67

  step = Math.min(step, balls[end - 1].d - PP.RECOIL_FLOOR);

グループの最後尾が d = -144 より奥へは行きません。
これがないと、玉が洞窟の奥深くへ押し込まれ、戻ってくるのに時間がかかりすぎます。

終了条件は「速度が 8 px/s を切る」か「最大距離まで押した」。


## 7-9 relax — 重なりの解消

  js/chain.js:159-168
    function relax(lane, record) {
      var balls = lane.balls;
      for (var i = balls.length - 2; i >= 0; i--) {
        if (balls[i].d < balls[i + 1].d + D) {
          var nd = balls[i + 1].d + D;
          if (record) balls[i].slide += balls[i].d - nd;
          balls[i].d = nd;
        }
      }
    }

たった10行ですが、とても賢い処理です。

  balls[i].d < balls[i+1].d + D

は「i 番目の玉が、i+1 番目の玉にめり込んでいる」という意味です
(i のほうが前、i+1 のほうが後ろ)。めり込んでいたら、前へ押し出します。

【なぜ後ろから前へ(i = length-2 → 0)なのか】

一番後ろから始めると、押し出しが **前へ伝播** します。

  初期: d = [100, 60, 40, 20]     (D = 48 なので理想は [164, 116, 68, 20])
  i=2:  40 < 20+48=68  → d[2] = 68     [100, 60, 68, 20]
  i=1:  60 < 68+48=116 → d[1] = 116    [100, 116, 68, 20]
  i=0:  100 < 116+48=164 → d[0] = 164  [164, 116, 68, 20]

1回のループで完全に解けます。

もし前から後ろへ(i = 0 → length-2)やると、

  i=0:  100 < 60+48=108 → d[0] = 108
  i=1:  60 < 40+48=88   → d[1] = 88   ← でも d[0]=108 は 88+48=136 より小さい!
  i=2:  40 < 20+48=68   → d[2] = 68

1回では解けず、何度も繰り返す必要が出ます。

  【GIF: chain/relax-pushout.gif】
    めり込んだ列に対して i = length-2 → 0 のループが走り、
    押し出しが後ろから前へバケツリレーされて1回で整列する。
    前から回した場合との比較も。

【record 引数】

  if (record) balls[i].slide += balls[i].d - nd;

record = true のときは、押し出した量を slide に記録します。
これは発射玉の割り込み(insertShot)から呼ぶときだけ使います。

slide は「表示上のずれ」です。物理的には玉はもう新しい位置にいますが、
描画は少し遅れてついていきます。

## 8-2 resolveMatchAt — 同色の連なりを数える

  js/chain.js:571-584
    function resolveMatchAt(lane, index, chained) {
      var balls = lane.balls;
      if (index < 0 || index >= balls.length) return false;
      var c = balls[index].color;
      if (c === null || c === undefined) return false;
      var i = index, j = index;
      while (i > 0 && balls[i - 1].color === c &&
             balls[i - 1].d - balls[i].d <= D + 1) i--;
      while (j + 1 < balls.length && balls[j + 1].color === c &&
             balls[j].d - balls[j + 1].d <= D + 1) j++;
      if (j - i + 1 < 3) return false;
      popRun(lane, i, j, chained);
      return true;
    }

index の玉を起点に、左右へ同色をたどって範囲 [i, j] を広げます。

  条件は2つ、両方満たす必要があります:
    ・色が同じ (balls[i-1].color === c)
    ・接触している (距離が D + 1 以下)

離れていたら打ち切ります。見た目で繋がっていない玉は消えません。

  c === null のチェックは宝玉よけです。宝玉の color は null なので、
  宝玉を起点にすると必ず false を返します。

3個未満なら何もせず false を返します。3個以上なら popRun へ。

  【GIF: chain/resolve-match.gif】
    起点の玉から左右へポインタ i, j が伸びていく。
    同色なら伸び、色が違うか隙間があれば止まる。
    最後に j - i + 1 を数えて 3 以上かどうかを判定。

## 8-4 destroyRange — 実際に配列から取り除く

  js/chain.js:616-636
    function destroyRange(lane, i, j) {
      var balls = lane.balls;
      var removed = balls.splice(i, j - i + 1);
      if (lane.recoil && removed.indexOf(lane.recoil.anchor) >= 0) {
        lane.recoil.anchor = balls[i] || null;
        lane.recoil.inherited = true;
        if (!lane.recoil.anchor) lane.recoil = null;
      }
      removed.forEach(function (b, k) {
        var p = lane.rail.posAt(b.d + (b.slide || 0));
        b.view.x = p.x; b.view.y = p.y;
        PP.fx.particles(p.x, p.y, b.color, k * 15);
        createjs.Tween.get(b.view, { override: true })
          .wait(k * 15)
          .to({ scaleX: 1.35, scaleY: 1.35 }, 60)
          .to({ scaleX: 0, scaleY: 0, alpha: 0 }, 100, createjs.Ease.backIn)
          .call(function () { if (b.view.parent) b.view.parent.removeChild(b.view); });
      });
      return removed.length;
    }

  Array.splice(開始, 個数) は配列から要素を取り除いて、取り除いたものを返します。

反動の引き継ぎが重要です。

  if (lane.recoil && removed.indexOf(lane.recoil.anchor) >= 0) {
    lane.recoil.anchor = balls[i] || null;
    lane.recoil.inherited = true;
  }

反動の起点(anchor)が消される玉に含まれていたら、
その後ろ(補給側)に残った玉へ引き継ぎます。
splice したあとの balls[i] は「消した範囲のすぐ後ろにいた玉」です。

inherited = true にすることで、applyRecoil が hitCd を再セットしないようにします
(js/chain.js:484-487)。引き継いだ玉は「まだぶつかっていない」からです。

演出は k(消える玉の並び順)ごとに 15ms ずつ遅らせます。
6個消えれば 0, 15, 30, 45, 60, 75 ms とずれ、パパパッと弾けます。

view.x / view.y をここで明示的にセットしているのは、
玉が配列から抜けたあとは renderChains が位置を更新しなくなるからです。
消える瞬間の位置で固定してから Tween に渡します。


## 8-5 joinAt — 消したあとの連鎖

  js/chain.js:639-646
    function joinAt(lane, index) {
      var balls = lane.balls;
      if (index > 0 && index < balls.length &&
          balls[index - 1].color === balls[index].color &&
          balls[index - 1].d - balls[index].d <= D + 1) {
        resolveMatchAt(lane, index, true);
      }
    }

玉を [i, j] の範囲で消した直後、その跡の前後がすでに接触していたら、
その場で連鎖判定します。

  消す前: ● ● [赤 赤 赤] ● ●
                ↑ ここを消す
  消した後: ● ● ● ●
              ↑ index。ここで前後が同色かつ接触していれば連鎖

「すでに接触していたら」というのが条件です。
隙間が空いていれば、そこは磁力の仕事になります(applyMagnet)。

joinAt → resolveMatchAt → popRun → joinAt → ... と再帰します。
1回の消去で4段、5段と連鎖することがあります。


## 8-6 割り込みのマッチは遅らせる

  js/chain.js:193-203

発射玉が割り込んだ瞬間には判定しません。0.14 秒待ちます。

理由は演出です。割り込んだ玉は着弾点から列の位置へ「滑り込む」アニメを
しています(章09)。そのアニメの途中で消え始めると、
「入る前に消えた」ように見えてしまいます。

ループ中に splice で要素を削除するからです。前から回すと、

これは JavaScript の配列を安全に削除しながら回る定石です。
コード中の他の場所(powerups.js:77、cannon.js:562 など)でも同じ形が使われます。

## 8-8 割り込み insertShot

発射玉が当たったときに呼ばれます(cannon.js から)。

  js/chain.js:683-709
    function insertShot(lane, sh, hitIndex) {
      var balls = lane.balls;
      var hit = balls[hitIndex];
      var p = lane.rail.posAt(hit.d);
      var dot = (sh.x - p.x) * p.tx + (sh.y - p.y) * p.ty;
      var view = PP.ball.makeView(sh.color);
      PP.layers.ballUnder.addChild(view);
      var newBall = {
        color: sh.color, wave: hit.wave, view: view, pull: 0, slide: 0,
        ins: { x: sh.x, y: sh.y, t: PP.INSERT_TIME }
      };
      var at;
      if (dot > 0) {
        newBall.d = hit.d + D;              // 前に割り込み
        at = hitIndex;
      } else {
        newBall.d = hit.d;                  // 後ろに割り込み
        at = hitIndex + 1;
      }
      balls.splice(at, 0, newBall);
      PP.audio.hit();
      relax(lane, true);
      lane.pendingMatches.push({ ball: newBall, t: PP.INSERT_TIME });
    }

### 内積で前後を決める

  var dot = (sh.x - p.x) * p.tx + (sh.y - p.y) * p.ty;

これが章04 で用意した接線 (tx, ty) の出番です。

**内積(dot product)** とは、2つのベクトルの「向きの一致度」を測る計算です。

  A・B = Ax × Bx + Ay × By

  ・同じ向きなら正
  ・直角なら 0
  ・逆向きなら負

ここでは:

  A = (弾の位置 - 当たった玉の位置)  … どちら側からぶつかったか
  B = (tx, ty)                         … レールの進行方向

つまり「弾は、当たった玉から見てレールの進行方向側にいるか?」を聞いています。

  dot > 0 → 弾は進行方向側(= 樽側 = 前)にいる → 前に割り込む
  dot ≤ 0 → 弾は逆側(= 洞窟側 = 後ろ)にいる → 後ろに割り込む

これで、どんなに道が曲がりくねっていても正しい側に入ります。

### splice の位置

  balls は「先頭(d 最大)が [0]」の順で並んでいます。

  前に割り込む場合:
    d = hit.d + D(当たった玉より D だけ樽寄り)
    配列上は hit より前 → at = hitIndex

  後ろに割り込む場合:
    d = hit.d(当たった玉と同じ位置。このあと relax が押し出す)
    配列上は hit の次 → at = hitIndex + 1

後ろに割り込むとき d を hit.d と同じにするのは意図的です。
完全に重なった状態から relax(lane, true) で押し出すと、
記録された slide によって「ぐいっと押し広げる」表示になります。

### ins — 滑り込みアニメ

  ins: { x: sh.x, y: sh.y, t: PP.INSERT_TIME }

弾が当たった座標を覚えておきます。描画側でこれを使います。

  js/main.js:263-269
    if (b.ins) {
      var k = 1 - b.ins.t / PP.INSERT_TIME;
      k = 1 - (1 - k) * (1 - k);           // quadOut
      vx = b.ins.x + (p.x - b.ins.x) * k;
      vy = b.ins.y + (p.y - b.ins.y) * k;
      b.view.scaleX = b.view.scaleY = 1 + 0.3 * (1 - k);
    }

  k は 0(着弾直後)→ 1(定位置)へ進む進捗。
  k = 1 - (1-k)² は quadOut のイージング(最初速く、だんだん遅く)を手計算したもの。
  座標は着弾点から定位置へ線形補間。
  大きさは 1.3 倍から 1.0 倍へ縮む(「ドン」と入る感じ)。

  ins.t は updateAnims で減らされ、0 になったら ins = null になります
  (js/chain.js:180-183)。

  【GIF: cannon/insert-shot.gif】
    ★ 最重要 GIF。
    ① 弾が飛ぶ
    ② 命中した玉と接線ベクトルを表示
    ③ dot = (弾 - 玉)・(tx, ty) の計算を可視化(矢印と符号)

    ⑤ relax で列が押し広がる(slide が付く)

## 8-10 まとめ: 1フレームで起きること

  ① updateWaveTimer  次の波のタイマーを減らし、条件が揃えば startWave
  ② spawnBalls       洞窟口が空いていれば玉を追加。波の最後に宝玉
  ③ groupStarts      接触しているまとまりの区切りを求める
  ④ snapshotJoints   いま空いている隙間を記録
  ⑤ advance          最後尾グループと宝玉持ちグループだけ前進
  ⑥ applyRecoil      反動があれば、その区間を押し戻す
  ⑦ applyMagnet      同色の隙間を縮める。閉じたら impact
  ⑧ relax            めり込みを後ろ→前へ押し出して解消
  ⑨ resolveJoints    ④で記録した隙間が閉じていたらマッチ判定
  ⑩ updateTreasures  宝玉の解放/粉砕
  ⑪ updateAnims      slide・ins・hitCd の時間を進める
  ⑫ updatePendingMatches  割り込みアニメが終わった玉のマッチ判定

これを全レーンぶん繰り返します。そのあと main.js の renderChains が
すべての玉の d を座標に変換して view を置き、stage.update() で描画されます。
