# 保守ガイド

## 最初に読む順番

このゲームは通常のJavaScriptとCreateJSで動きます。`index.html`を直接開けます。開発サーバー、ビルド、TypeScriptは不要です。

1. `js/config.js`で速度・色・難易度などの設定を確認します。
2. `js/game-state.js`で、得点・玉・弾をどこに保存しているか確認します。
3. `js/main.js`の`tick`で、1フレームの更新順序を読みます。
4. 変更したい機能のファイルへ進みます。

`PP`は各ファイルが機能を公開する共通の名前です。`PP.game`は実行中のデータです。各ファイルを囲むIIFE（すぐ実行する関数）は、内部変数が他のファイルと衝突するのを防ぎます。読み込み順は`index.html`のscriptタグに明記しています。

## 何を変えるとき、どこを読むか

| 変更したいもの | 入口 |
|---|---|
| 基本速度・難易度・色・音量・風・夜 | `config.js`の`PP.SPEED`、`PP.DIFFICULTY`、`PP.PALETTE`など |
| 特定ステージの速度 | `config.js`の`PP.STAGE_SPEED`、またはコースの`speed` |
| コースの形・橋・トンネル | `courses.js`の`PP.COURSES`、画面下のコースエディタ |
| 自作コースの追加 | `my-course.js`、`PP.courseAPI.create(spec).register()` |
| ボス・骸骨の強さ | `combat-config.js` |
| 強化カード・虹玉の設定 | `upgrade-config.js` |
| 開始・クリア・リトライ・継続 | `session.js` |
| チェーンの移動 | `chain.js` |
| 同色の接触判定・宝の担当判定 | `chain-rules.js` |
| 玉の表示位置・橋の上下の描画順 | `chain-view.js` |
| 大砲の見た目・照準・発射 | `cannon.js` |
| 飛ぶ弾の移動・衝突 | `projectiles.js` |
| ボスの状態と予兆 | `boss.js` |
| ボスの発射パターン・妖弾・本体描画 | `boss-attacks.js`、`boss-projectiles.js`、`boss-view.js` |
| 編集データと取消履歴 | `editor-model.js` |
| 編集プレビューとWebGLキャッシュ | `editor-view.js` |
| エディタの操作・パネル・入出力 | `editor.js` |
| 音源の差し替え | `audio.js`、`SE/`、`BGM/` |

### 小さな変更の進め方

設定を一つ変え、ブラウザーを再読み込みして効果を確認してください。たとえば`PP.SPEED.hole`は樽側の速度（px/秒）です。ただしステージ別の上書きや難易度倍率もあるため、コースと難易度を固定して比べます。黒玉・コイン回復は実装済みです。古い課題番号はコードを読む目印として残っています。

色を増やすときはパレットだけでなく`PP.COLORS.max`と難易度別の上限も確認します。コースを増やすとキャンペーンの最終ステージも変わります。ボスを最後に置きたい場合は`PP.COURSES`の順序を調整してください。

## データと更新順序

`main.tick`はポーズを確認し、プレイ中なら`session.updatePlaying(dt)`を呼びます。時間の単位は秒、画面座標と距離の単位はpxです。

```text
入力 → チェーン移動 → 発射弾の衝突 → アイテム・時間効果
     → 風・夜・強化・敵の攻撃 → 勝敗 → 残り時間・掃討
     → 背景・演出・照準 → チェーン描画 → stage.update
```

順序を入れ替えると、衝突位置、残り時間、勝敗が変わります。ボスの勝利が確定したフレームは樽あふれによる敗北へ移行しません。HPが0になってから勝利確定までの撃破演出は従来どおりです。

各レーンの`balls[0]`が樽に最も近い玉です。`d`は洞窟からのレール距離で、配列の後ろほど小さくなります。画面上のx座標順ではありません。レーン同士の玉を一つの配列に混ぜないでください。

`PP.game`自体を別オブジェクトに置き換えないでください。ゲーム進行は`PP.session`、弾の配列は弾処理、編集データはエディタモデルが担当します。既存の`PP.playCourse`、`PP.retryLevel`、`PP.skipIntro`、`PP.returnToTitle`も引き続き使えます。

| 操作 | 保持・初期化 |
|---|---|
| `session.newRun(level)` | 得点・コイン・強化・継続記録を初期化 |
| 次のコース・ライフ消費リトライ | 得点・コイン・強化を保持し、コース内の玉・弾・効果を初期化 |
| `session.continueRun()` | 同じコースと強化を保持。得点・コインを0にし、ライフと虹玉を補充 |
| `PP.playCourse(course)` | 従来互換の試遊。コースをレベル1として開始。周回の得点や強化は初期化しない |
| `PP.returnToTitle()` | コースと一時表示を片付け、周回データを初期化 |

### 後片付け

表示物を画面から外すだけではTweenは止まりません。`lifecycle.removeView`はその表示物と子のTweenを止めてから外します。`clearLanes`は玉をプールへ戻し、`clearShots`は飛行弾を片付けます。レーン配列を置き換える**前**に古いレーンを片付けてください。全Tweenの一括停止は永続UIまで止めるため使いません。

ボスの`battle`は、そのボスの制御・弾・攻撃・描画に渡す同一のオブジェクトです。ヘルパー間で必要な関数は生成時に明示して渡します。値をコピーして渡すと、撃破・攻撃キャンセル後に古い状態を参照してしまいます。

### コースの互換性

JSONの`v: 2`と旧形式の`ctrl`を維持しています。`speed`、`raisedOver`、`boss`、出現率などは、エディタに入力欄がなくても保存・取消・やり直しで保持します。`corner: 0`などの有効なゼロ値を`||`で既定値に置き換えないでください。

保存キー`pp.course.*`は従来どおりです。`index`は一覧用の予約名なので保存名に使えません。壊れた一覧は、残っている読み取り可能なコースから復元します。壊れたコース本体や無関係なデータは削除しません。以前の不具合で既に失われたデータ自体は復元できません。

## 確認方法

開発用の自動テストはNode.js 18以降で動作します。追加パッケージのインストールは不要です。

```sh
npm run check
npm test
npm run smoke
npm run test:browser
```

- `check`: JavaScript全体の構文確認。
- `test`: データ保持、保存失敗、接触判定、撃破、読み込み遅延、後片付けの回帰テスト。
- `smoke`: Chromiumで`file://`の起動を確認。
- `test:browser`: Canvas2D/WebGL、固定乱数の全コース、ボス攻撃、エディタ、状態遷移を確認。

ブラウザーテストはインストール済みのBrave／Chrome／Edge／Chromiumを使います。自動検出できなければ環境変数`PP_BROWSER`に実行ファイルのパスを指定してください。通常の利用プロファイルや保存データは使わず、一時プロファイルで実行します。

画面が止まる場合は開発者ツールのConsoleで最初の例外を確認します。`?level=6`でボス、`?gl=0`でCanvas2D、`?gl=1`でWebGL、`?editcourse=1`でエディタを起動できます。正常時の状態は`PP.game.state`、ボスの状態は`PP.boss.getState()`で確認できます。

自動テストは完全な通しプレイ、スマートフォン実機、Safari、発熱や音質の保証ではありません。入力や描画を変えた際は実機でも確認してください。
