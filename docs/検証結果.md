# リファクタリングと不具合修正の検証結果

## 変更内容

`index.html`を直接開く構成とCreateJSを維持し、設定・コースデータ・共有状態、ゲーム進行、玉の描画、発射弾、ボスの攻撃と弾、エディタのデータと描画を分離しました。既存の`PP`公開APIとコースJSON v2、localStorageの保存キーを維持しています。

`main.js`は約1,440行から約400行になり、初期化と更新順序を追いやすくしました。共有状態の定義にはJSDocを追加しました。役割と変更箇所の入口は[保守ガイド](保守ガイド.md)を参照してください。

作業開始前からの`README.md`、`config.js`、`night.js`の変更を保持しています。`night.js`は今回変更していません。

## 不具合と確認方法

| 修正した問題 | 回帰確認 |
|---|---|
| 反射弾による撃破後の二重削除 | 通常命中・撃破・複数弾の単体テストと、実ブラウザーで本物の撃破処理を実行 |
| 同じフレームの勝利と樽あふれ | クリア状態・6,000点・ライフ非減少を確認 |
| 保存名`index`による一覧破損 | 書き込み前の拒否、破損一覧の復元、保存失敗の通知と巻き戻し |
| コース設定の欠落 | APIの複製・JSON、エディタの読み書き・保存・取消・やり直しで保持 |
| ゼロ値の無視 | ゼロと未指定の区別、角丸0の直角経路の長さを確認 |
| ポーズ中のエディタ移行による停止 | エディタ起動の拒否、APIからの新規プレイで停止解除 |
| 画面移行後に残るTween | 宝の光・弾の火花を解除し、永続UIのTweenは維持 |
| 音声読み込みと共有URLの競合 | タイムアウト後の通知を無視。音声とエディタの準備順を両方確認。遅い完了でプレイをタイトルに戻さない |
| WebGLでのエディタ表示 | キャッシュ内の画素と、ハンドルのイベント判定・ドラッグを確認 |
| 強化カードの予告と実効果の違い | コインの下限と継続ボーナス込みの虹玉容量を、カード表示と適用後の値で確認 |

## 実行結果

環境はWindows、Node.js 18.18.0、インストール済みBraveのChromiumヘッドレス実行です。ブラウザーテストは一時プロファイルと`file://`を使用しています。

| コマンド | 結果 |
|---|---|
| `npm run check` | JavaScript 53ファイルの構文チェック成功 |
| `npm test` | 19件成功 |
| `npm run smoke` | 全モジュールの読み込み・初期化・起動成功 |
| `npm run test:browser` | Canvas2D／WebGL、共有URL、タッチ入力のシナリオ成功 |

ブラウザーの回帰テストでは次を確認しました。

- 全6コースを固定乱数・1/60秒刻みで各最大600フレーム進行。敗北時はそのコースの進行確認を終了します。テスト用の射撃パターンではコース5が敗北状態になります。
- 玉の距離が有限で、レーン内の並び順が保たれること。両描画方式の得点・残り玉数・状態が一致すること。
- ボス全10攻撃を各720ステップ更新し、例外がないこと。
- 同色消去とレーンの独立性、複数の離れた範囲を爆弾・ミサイルで消去した後の玉、宝玉の保護。
- 逆走中は停止効果の残り時間を保持し、逆走終了後に減算を再開すること。
- リトライ時の得点・強化の保持、継続時の補充、タイトル復帰時の初期化。
- エディタのJSON入力・出力、保存、ドラッグ、キーボードによる取消・やり直し。
- `?course=`と`?editcourse=`の起動、および両方指定した場合のエディタ優先。
- Chromiumのタッチエミュレーションで、実際のpointerイベントによる発射・移動・指を離した際の停止。
- シナリオ終了後に通常のメインループを戻し、実際のtickで例外がないこと。

## 確認範囲の限界

完全なキャンペーン通しプレイ、スマートフォン実機、Safari、音質・発熱・長時間の性能測定は未実施です。タッチエミュレーションは実機での操作感を保証するものではありません。今回の変更による性能向上の数値は主張していません。

以前の保存不具合で既に失われたコース本体は復元できません。残っている有効なコースから保存一覧を復元する対応です。
